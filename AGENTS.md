On 2026-10-14 the user asked for seven items and left for twelve hours. Six are implemented; the fifth was declined as asked (referencing another project's anti-ban tactics to evade a service's account risk controls is not something this project will do). The six:

1. **Designated browser per environment, chosen at attach and terminal time.** The attach wizard gains a third step, shown only when the target network group has another browser (same network group and same node as the environment); it offers those browsers plus "system default browser". The terminal page shows the same choice as a chip in its context strip, with the chooser as a modal. With no candidate the step is skipped and the page says links will go to the system default browser. The choice is persisted on the application binding (`browserProfileId`, allowlisted in `application-store.mjs`) and in the terminal's `workspace.json` next to the working directory. Changing it never restarts anything: links resolve it when they open. `AGENTS.md`'s rule stands — a link opened outside the environment must be shown as such.

2. **Terminal and application links use that browser.** A fenced terminal gets a per-environment `bin` directory prepended to its own PATH with an `open` replacement (and `browser`/`envara-open` for `$BROWSER` callers) that reports the link to Envara over a private Unix socket authenticated by a per-environment token (`electron/terminal-link-channel.mjs`; socket 0600 inside a 0700 directory, one URL per request, no other field accepted). A failed report exits non-zero rather than starting anything on the host. For a link macOS hands to a browser — an attached application's sign-in window, which no shim can see — there is a dockless helper (`native/macos-link-router`, AppKit, ad-hoc signed) registered as the system handler for `http`/`https`; it sends the URL and the sender's pid to Envara, which walks the process table to the managed instance (by its sealed copy path) or to a terminal session, then opens the link in that context's designated browser. Anything else — Envara not running, an unrelated sender, a refusal, a three-second timeout — opens in the browser that was the default before, so the user's links keep working. Enabling it changes a host-wide setting, so it happens only through macOS's own confirmation accepted by the user, only from Settings ("打开链接"), and is reversible there; the previous default is remembered and restored.

3. **Sign-in data shrinks by ~98%.** Measured: 835 MB for Notion was 723 MB of `Partitions/notion/Service Worker` plus 83 MB of `Cache`, against ~20 MB of actual login state. `electron/application-data.mjs` prunes only regenerable Chromium caches (a named allowlist) at the data root, `Default` and every `Partitions/*`, and reports the bytes freed.

4. **Stopping an application now deletes its sealed copy automatically.** After a stop with a confirmed clean cleanup, the session manager runs housekeeping on the already-open shared authorized session (no extra administrator prompt): `reclaimApplicationStorage` for the registration, then the cache prune above. Quitting Envara waits for it. The per-registration `UserData` — the sign-in state — is never touched by this path.

5. **Sign-in data has its own tab.** "登录数据" is the third segment of the attached-applications page: one compact row per environment and application, with its size, a delete button, and a lock while the software runs. Deleting goes through a confirmation that says the next start needs a new sign-in and that the application and its environment are unaffected. `electron/sign-in-data.mjs` builds the rows and remembers application names so a row stays readable after its binding is removed; `signInData`/`deleteSignInData` are the IPC. The old in-row eraser and its storage panel are gone; removing a binding now says the sign-in data stays and where to delete it.

6. **Frontend polish.** The sidebar footer is one owner line (storage size appears there only when it is non-zero); the four attached-application notes are a collapsed disclosure; the terminal page and attached-application rows carry the link-browser chip described above. The full-page capture harness (`build/local-verification/ui-capture`, `ENVARA_CAPTURE_PAGES=all|settings|signin|clear`) was extended and every page reviewed from screenshots.

Cross-cutting: `LinkSocketServer` serves both the terminal shim socket and the router socket; `scripts/build-macos-link-router.mjs` builds the helper into `build/app-routing/macos-link-router` and `dist:mac` runs it. Not yet verified by the user: the LaunchServices default-browser change and the router's behaviour inside a running attached application (attribution was measured with a stand-in sender: macOS reports the direct sender's pid, and a short-lived helper resolves through its ancestry). Decisions that follow:

- **An environment's own browser is a link browser, and the default.** The earlier rule offered only *other* browsers of the group, so an environment alone on its network had none and every link went to the host browser. Now the candidates are the environment itself first, then its group's other browsers on the same node. Unset means the environment's own browser; `system` (`SYSTEM_BROWSER`) is an explicit choice of the host default browser and is still described as leaving the environment; a saved browser that is no longer on the network falls back to the environment's own browser, never out of it. The rule lives in `electron/link-router.mjs`, and `src/link-browser.mjs` mirrors it for the page. The attach wizard's browser step is now always shown.
- **New terminal = network, browser, folder.** The network list is the nodes the environments use, each showing its measured egress (IP · country · timezone). The browser list is the environments on that network plus the system browser; the chosen browser's environment hosts the terminal (its tool configuration, history and timezone), and choosing the system browser saves `system` on that environment. The folder comes from the native picker (`pickTerminalDirectory`), which returns only a one-shot, time-limited token; `openTerminal({ fresh: true, directoryToken })` always starts a new process, even while others run, and a directory path is never accepted from the renderer. Running terminals keep their own folders; the picked folder becomes the environment's default for next time, and changing the directory no longer drops the saved link browser.
- **The terminal footer says what the fence enforces.** A fenced session reports "经「<network name>」出网，已加网络围栏：不支持代理的程序会连不上，不会直连。" instead of the older proxy wording that suggested local addresses go direct.
