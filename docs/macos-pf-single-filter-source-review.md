# Fixed single-FILTER source review

This is a source review and an inert mock result. It does not establish the current host's complete PF ABI, explain the cause of earlier namespace retention, authorize PF activation, or open protected application launch. Darwin 27's matching XNU source is unpublished. No installed frozen 832 component was changed by this work.

The new primitive accepts one fixed UUID, `a85314b8-5b24-4784-95ec-47b739c2e841`, and exactly `EMPTY → DENY → EMPTY`. Each transaction contains one `PF_RULESET_FILTER=1` entry. Its anchor and owner are `io.envara.pf.run.a85314b8-5b24-4784-95ec-47b739c2e841`. The deny template is outbound IPv4 TCP to the documentation address `198.51.100.42/32`, destination port `44441`, quick drop, no state, no route, no interface, no UID/GID match and no anchor call. There is no arbitrary rule input or TABLE transaction.

The layout comes from [Mullvad pfctl-rs at commit 273e96b](https://github.com/mullvad/pfctl-rs/blob/273e96bec0f5b983f16cfd43b6512f4c97a3f848/src/ffi/pfvar.rs): transaction element 1032 bytes (`rs_num` 0, anchor 4, ticket 1028); transaction envelope 16 bytes (array pointer 8); pool request 1136 bytes (ticket 4, anchor 19, pool address 1048). The static destination wrapper is 48 bytes; `pf_rule_addr` is 64 bytes, with its transport at 48, equality operator at 52 and negation at 56. These assertions are source compatibility checks, not native host acceptance. The dependency is MIT/Apache-2.0 licensed; its identity is preserved.

[Apple XNU at commit f6217f8, pf_ioctl.c](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/net/pf_ioctl.c) distinguishes the ordinary ruleset path from TABLE dispatch in `DIOCXBEGIN`, `DIOCXCOMMIT` and `DIOCXROLLBACK`. `pf_begin_rules` finds/creates the named ruleset, clears that class's inactive queue, increments its uint32 ticket and releases its acquired ruleset reference. The direct one-element FILTER vector cannot invoke `pfr_ina_begin`. This supports testing the single-class alternative; it does not prove that TABLE handling caused the observed host retention. Namespace removal still has separate reference, child, table and open-transaction conditions in [pf_ruleset.c](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/net/pf_ruleset.c).

The exact successful BEGIN reply owns the returned uint32 ticket, including a valid wrap to zero. An error or a changed envelope leaves the ticket unknown, even if its buffer contains a value. It causes no guessed rollback or retry. Any later failure poisons the context. A precommit failure permits at most one rollback of the exact returned ticket and fixed FILTER entry, after a fresh guard. A COMMIT error remains uncertain even if that rollback returns success: the pinned rollback can acknowledge a missing, mismatched or already closed transaction without undoing active rules. A successful COMMIT followed by failed verification causes no further mutation. Callback reentry cannot restore a poisoned context; callers must serialize access. Kernel-blocked ioctls have no hard deadline inside this primitive.

Every mutating call requires the caller's fresh PF-disabled, exact leased own root-hook and descriptor proof. Initial installation, authorization, exclusive runtime lease, frozen manifest verification, root insertion/deletion and cleanup truth remain outside this component. It neither opens `/dev/pf` nor changes PF enablement, states, routing, DNS or any production runtime.

`DIOCADDRULE` requires the global `ticket_pabuf`. The pinned `DIOCBEGINADDRS` implementation empties global `pf_pabuf` and increments that ticket even when the proposed filter has no address pool. The component issues one all-zero BEGINADDRS request and never ADDADDR; this is not isolation from a concurrent foreign pool transaction. The caller must explicitly authorize that controlled test stage. GETRULE copyout redacts the pool list pointers, so full rule bytes alone do not establish an empty kernel pool. Global pool concurrency remains an unaccepted gate.

Readback uses GETRULES, the exact active transaction ticket, GETRULE for the one deny rule and a second GETRULES. It verifies count and full request/rule bytes. Only pinned copyin/setup/copyout results enter the expected template: creator UID/PID, `rpool.af`, and each absent skip target's `-1` index. State, source-node and packet counters must be zero; opaque semantic bytes are compared, not masked away. Passing this readback does not verify all classes, root absence or namespace retirement.

For historical comparison, [original OpenBSD pfctl.c at commit 9cca9e0](https://github.com/openbsd/src/blob/9cca9e01137b0f1af75437f1b6e6b6f8e551a4ec/sbin/pfctl/pfctl.c) sets `-R` to FILTER only. Its transaction construction adds SCRUB and FILTER conditionally, and TABLE only when `PFCTL_FLAG_TABLE` is selected. Its optimization can create tables. This original implementation is not proof of Apple's installed `pfctl -R`; the canary does not use that CLI alternative.

Inert validation: `node --test tests/macos-pf-single-filter-transaction.test.mjs` passed 48 tests. All mutations used a callback with fake descriptor 123; a real ioctl fallback aborts in the harness. Clang C11 with `-O2 -Wall -Wextra -Werror` passed the harness and the standalone source syntax check. An independent read-only review rechecked the poison, exact-ticket, rollback, zero-ticket and narrow-rule boundaries. Actual empty/deny/empty execution, root DELETE, namespace retirement and native routing remain separate acceptance work.
