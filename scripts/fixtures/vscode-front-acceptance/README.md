# Local VS Code extension-host acceptance fixture

This unpacked, private extension is an opt-in acceptance probe for an Envara-owned VS Code trial. It does not install itself or alter settings. It performs no subprocess execution and reads only its own configuration. It never reads proxy credentials, personal settings, extension lists or runtime pins.

After inspecting the source, place a physical copy of this folder directly inside the trial registration's `Extensions` directory before starting managed VS Code. The fixture waits up to 60 seconds after activation for its own `probe-config.json`, polling the local file only. Once the managed front is known, atomically write that file in the copied folder with a fresh `runId`, the verified loopback SOCKS front port and independently measured environment egress IP. Build the complete JSON under another filename and rename it into place: an invalid or incomplete config is refused immediately, without retries. The source example intentionally has no working port or private address. Required `deniedLoopbackPort` must name two separately owned listeners on `127.0.0.1` and `::1`, at the same port, whose outside-fence positive controls have succeeded; never use the front port. Independently confirm no connections reach either listener during the probe. Do not open the user's ordinary VS Code to run this fixture.

`probe-activation-<pid>-<timestamp>.json` records `waiting-for-config`, then `config-received`, `config-timeout`, `config-invalid-or-unreadable` or `cancelled`, with safe error codes. Waiting, timeout, invalid configuration and cancellation perform no network probe. Deactivation cancels the local polling timer. Receiving a valid configuration ends the wait; the network sequence is still a single attempt with no retry or fallback. After timeout or invalid configuration, a newly authorized managed restart is required to activate again.

The extension activates in a local Node extension host on `onStartupFinished` and atomically creates `probe-result-<runId>.json` in its own isolated extension directory, first as `running`, then with the final result through the same held file descriptor. The same `runId` is not executed again; use a new one for a newly authorized observation. If the physical extension directory is not under the expected UUID-scoped Envara application data root, it returns without writing or networking. It records process IDs and only safe path/argument comparisons, not raw arguments or environment values. Extension hosts need not inherit the main process's Chromium arguments; absent argument flags are recorded but are not failures. The explicit port configuration handles that normal case.

The probe checks the consistency of actual HOME, temporary/cache/config paths, VS Code global storage and the sealed executable; these comparisons alone do not prove physical directory isolation. It attempts one IPv4 and one IPv6 TCP connection to the owned loopback listeners, expecting `EPERM` or `EACCES`; timeouts and connection refusal are inconclusive failures, never successful denials. It then connects only to the selected loopback front, sends the front's no-auth SOCKS5 greeting, requests `api.ipify.org:443` by domain through SOCKS, and performs certificate-verified TLS on that existing socket. One bounded HTTP request retrieves the public IP. No local DNS call, redirect, reconnect, retry or direct fallback occurs. The route stages distinguish TCP reachability, authorization, upstream tunnel establishment and verified TLS. Overall `passed` also requires equality with `expectedEgressIp`. The entire network sequence is bounded to roughly 15 seconds.

For evidence, inspect the final JSON and independently correlate its PID/PPID with the managed VS Code process family. Keep the result local because it includes the measured egress IP. A passing result plus the outside controls proves this Node extension host's path consistency, direct-loopback TCP denials and selected-front public-IP request. It does not prove non-loopback direct TCP or UDP denial, Marketplace traffic, real account login, all VS Code subprocess types, XPC/system delegates, Keychain isolation, arbitrary native software protection or guard-crash safety. Remove only this fixture's isolated extension folder after acceptance; do not delete the environment's user data.
